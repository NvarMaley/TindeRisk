# RiskMatch Project Documentation

These documents form the project's internal operating guide. They do not constitute the course “report”: the assignment requires code on GitHub, a Streamlit application, and a 15-minute pitch.

Recommended reading order:

1. [`01_PROJECT_FRAMEWORK.md`](01_PROJECT_FRAMEWORK.md) — the requirements, the client, the scope, and the success criteria.
2. [`02_COURSE_ALIGNMENT.md`](02_COURSE_ALIGNMENT.md) — where each course chapter applies and which limitations must be observed.
3. [`03_METHODOLOGY.md`](03_METHODOLOGY.md) — scientific protocol, data, models, and validation.
4. [`04_EXECUTION_PLAN.md`](04_EXECUTION_PLAN.md) — exact sequence of work, dependencies, and completion criteria.
5. [`05_DECISIONS.md`](05_DECISIONS.md) — decisions to be made, the selected option, and the rationale.
6. [`06_EXPERIMENT_LOG.md`](06_EXPERIMENT_LOG.md) — hypotheses, tested variants, and decisions made to limit data snooping.
7. [`07_USER_JOURNEY.md`](07_USER_JOURNEY.md) — risk categories, portfolio cards, client selection, and live monitoring.

Additional execution documents:

- [`../CHECKLIST.md`](../CHECKLIST.md): daily task tracking.
- [`../RiskMatch_pipeline.ipynb`](../RiskMatch_pipeline.ipynb): reproducible, cell-by-cell demonstration.
- [`../CONTRIBUTING.md`](../CONTRIBUTING.md): branches, pull requests, and team rules.

Consistency rule: a method must appear in the application only if it has a definition in the methodology, a task in the checklist, an implementation in `src/`, a test in `tests/`, and reproducible evidence in the notebook or results.
